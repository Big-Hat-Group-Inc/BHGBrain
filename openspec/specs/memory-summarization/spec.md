# memory-summarization Specification

## Purpose

Every memory carries a `summary`: a single line of at most 120 characters derived from
its content at write time. The field is not decorative. It is the human-scannable label
`memory://list`, `memory://{id}`, and the CLI print for a memory; it is what session
inject falls back to when the full content does not fit the budget; and it is weighted
**2×** against `content` in fulltext ranking (`bm25(memories_fts, 1.0, 2.0, 2.0)`), so
its quality moves search results rather than merely decorating them.

This capability governs how that field is produced: a tiered summarizer — extractive by
default, optionally LLM-backed, with literal first-line truncation as the opt-out — and
the segmentation rules the extractive tier uses to decide what a sentence is. A summary
that is a fragment of a URL is worse than useless here, because the ranker trusts it
twice over.

## Requirements

### Requirement: Summaries SHALL be generated by a tiered summarizer instead of first-line truncation

When `auto_summarize` is `true` (the default), memory summaries SHALL be produced by
an extractive summarizer that considers the entire content, not only its first line,
selecting the sentence most representative of the content's term-frequency
distribution and truncating it to the configured maximum length.

The extractive tier's sentence segmentation SHALL treat `.`, `!`, and `?` as a
sentence boundary only when the punctuation run is followed by whitespace or the end
of the content, and SHALL always treat a newline as a boundary. Punctuation occurring
inside a token — the dots in URLs, domain names, semantic version strings, and
filenames — SHALL NOT be treated as a sentence boundary.

#### Scenario: Content containing a URL

- **WHEN** a memory is written whose content contains a URL or bare domain, such as
  `Special Agent K's website is https://specialagentk.eth.limo (ENS domain served via eth.limo)`
- **THEN** the persisted `summary` SHALL be derived from the whole sentence containing
  that URL, truncated to the configured maximum length
- **AND** the summary SHALL NOT be a fragment produced by splitting the URL at one of
  its own dots (e.g. `limo (ENS domain served via eth`)

#### Scenario: Content containing a version string or filename

- **WHEN** a memory is written whose content contains a semantic version
  (`v1.34.4`) or a filename with an extension (`summarize.ts`)
- **THEN** the sentence containing that token SHALL be scored and returned whole
- **AND** the token SHALL NOT be severed at its internal dots

#### Scenario: Multi-sentence content with a low-signal first line

- **WHEN** a memory is written with multi-sentence content whose first line/sentence
  carries little information (e.g. a heading) and a later sentence carries the
  substance
- **THEN** the persisted `summary` SHALL be derived from the higher-signal sentence,
  not unconditionally the first line

#### Scenario: Well-formed prose is unaffected

- **WHEN** content contains sentence-terminating punctuation that is followed by
  whitespace or the end of the content, and contains no intra-token punctuation
- **THEN** the persisted `summary` SHALL be identical to the value produced before this
  change, for the same content and configuration

#### Scenario: Single-sentence or single-line content

- **WHEN** content consists of a single sentence or single line
- **THEN** the persisted `summary` SHALL equal that sentence truncated to the
  configured maximum length, identical to the prior first-line-truncation behavior

#### Scenario: Summary length invariant

- **WHEN** any summarization tier (extractive, LLM, or literal truncation) produces
  a summary
- **THEN** the persisted `summary` SHALL NOT exceed the configured maximum length
  (120 characters by default)

#### Scenario: Existing summaries are not rewritten

- **WHEN** this change is deployed to an installation holding memories whose summaries
  were produced by the prior segmentation
- **THEN** those stored summaries SHALL remain as they are until the memory is next
  written or reverted
- **AND** no migration or backfill SHALL be performed as part of this change

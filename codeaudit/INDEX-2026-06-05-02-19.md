## Portfolio summary

Each proposal was audited as a standalone change **and** checked for spec compliance against its `proposal.md` / `tasks.md` / spec deltas. Overall the implemented code is high quality — **no Critical findings anywhere**, clean dependency posture, strong test discipline, and consistent dual-store handling. The real risk concentrates in **spec drift and unimplemented proposals**: two proposals are essentially not built (one is a live data-loss bug), several mark tasks "done" that aren't, and a recurring **"12 vs 10 bootstrap sections"** documentation drift spans three proposals.

**Headline risks (fix first):**
1. **`preserve-non-sliding-expiry` — live bug, unimplemented.** With `sliding_window_enabled=false`, every read clears T2/T3 TTLs (`lifecycle.ts:122-125` → `search/index.ts:253,261`). Data silently expires-resets on access.
2. **`fix-collection-scope-consistency` — not implemented at all.** Omitted-collection semantic/hybrid search silently falls back to collection `general` (`qdrant.ts:141`), hiding all other collections. All 3 reqs / 6 tasks Missing.
3. **`docker-support` — insecure default.** Container forces external bind (`0.0.0.0`, loopback off) with no token, so default `docker compose up` either crash-loops or exposes an unauthenticated memory API.
4. **Tasks marked done but not built** — `add-operations-security-reliability` (consolidation cluster + SQLite-lock retry), `add-tiered-memory-lifecycle` (scheduler/compaction/metrics/audit), `batch-retention-and-vector-cleanup` (GC failure-visibility).

## Cross-cutting themes

- **Silent degradation.** Multiple proposals swallow embedding/Qdrant failures with no log or metric (`add-mcp-contract-and-inject`, `bootstrap-memory-core`, `preserve-metadata-in-degraded-writes`, `batch-retention-and-vector-cleanup`). The codebase's own design docs repeatedly say "no silent degradation" — observability on the degraded path is the most common gap.
- **Bootstrap section count drift (12 vs 10).** `bulk-profile-import`, `interactive-bootstrap`, and the import tool description all advertise 12 sections while code/Zod/tests implement 10. Fix once in the shared section definitions and the docs together.
- **Tasks checked off without implementation.** Spec-compliance drift (not code defects) is the dominant theme — verify `tasks.md` against code before archiving any of: `add-operations-security-reliability`, `add-tiered-memory-lifecycle`, `batch-retention-and-vector-cleanup`, `fix-collection-scope-consistency`, `preserve-non-sliding-expiry`.
- **Cross-store ordering on delete/reset.** Several flows delete SQLite metadata before Qdrant vectors (or vice-versa) without compensation, risking orphans on partial failure (`interactive-bootstrap` reset, `new-device-bootstrap` hydration, `batch-retention` GC).
- **Non-constant-time bearer-token compare.** Recurs across `address-codereview-issues` and `harden-http-health-rate-limit-and-resource-bounds` — one shared fix.

## Recommended order of work

1. **`preserve-non-sliding-expiry`** — live data-loss bug; small fix (the SQLite layer already supports the `undefined`=no-change vs `null`=clear contract).
2. **`docker-support`** secure default — don't ship an unauthenticated external bind.
3. **`fix-collection-scope-consistency`** — implement the silent-`general`-fallback fix (cross-collection visibility/correctness).
4. Reconcile **`tasks.md`** vs code for the four "checked-off-but-unbuilt" proposals; un-check or implement.
5. Knock out the shared quick wins: 12→10 section docs, constant-time token compare, degraded-path logging/metrics.
